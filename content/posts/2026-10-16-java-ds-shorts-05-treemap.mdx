> **30초 요약** — **레드-블랙 트리**(자가 균형 이진 탐색 트리). 모든 연산 O(log n).
> HashMap보다 느리지만 **"가장 가까운 키", "이 구간의 키들"** 을 바로 물어볼 수 있다.

## 어떻게 생겼나

- 키를 `Comparable` 또는 생성자에 넘긴 `Comparator`로 비교해 트리에 배치한다.
- 삽입/삭제 때마다 회전으로 균형을 맞춰 높이가 항상 O(log n).
- `NavigableMap` 인터페이스를 구현한다 — 여기에 진짜 가치가 있다.

## 강점 — NavigableMap API

| 메서드 | 의미 |
|--------|------|
| `firstKey()` / `lastKey()` | 최소/최대 키 |
| `floorKey(k)` | k **이하** 중 가장 큰 키 |
| `ceilingKey(k)` | k **이상** 중 가장 작은 키 |
| `headMap(k)` / `tailMap(k)` | k 미만 / k 이상 구간 뷰 |
| `subMap(a, b)` | a 이상 b 미만 구간 뷰 |
| `descendingMap()` | 역순 뷰 |

## 약점

- `get/put` **O(log n)** — 단순 조회만 하면 HashMap이 훨씬 빠르다
- 기본 정렬(natural ordering)에서는 **null 키 불가**
- Comparator가 `equals`와 일관되지 않으면 "다른 객체인데 같은 키"로 덮어써진다
- 스레드 안전하지 않다 → 동시성 필요 시 `ConcurrentSkipListMap`

## 이럴 때 쓴다

- **구간 매핑**: 점수 → 등급, 금액 → 수수료율, 시각 → 요금제
- **시간순 데이터**: 타임스탬프 키로 "최근 1시간" 잘라내기
- 리더보드, 정렬된 결과가 항상 필요한 경우

```java
// 금액 구간 → 수수료율
TreeMap<Integer, Double> feeRate = new TreeMap<>(Map.of(
        0, 0.030,
        10_000, 0.025,
        100_000, 0.020
));
double rate = feeRate.floorEntry(35_000).getValue(); // 0.025

// 타임스탬프 이벤트에서 특정 구간만
TreeMap<Instant, Event> events = new TreeMap<>();
SortedMap<Instant, Event> lastHour =
        events.tailMap(Instant.now().minus(Duration.ofHours(1)));
```

## 기억할 것

- **정렬·범위·가장 가까운 값** 중 하나라도 필요하면 TreeMap
- 키만 필요하면 → `TreeSet` (같은 API: `floor`, `ceiling`, `subSet`) (6편)
- `if-else` 사다리로 구간을 판단하고 있다면 TreeMap으로 바꿀 신호
