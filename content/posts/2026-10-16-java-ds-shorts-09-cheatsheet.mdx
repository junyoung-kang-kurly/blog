> **30초 요약** — 기본값은 **ArrayList / HashMap / HashSet / ArrayDeque**.
> 순서가 필요하면 **Linked-**, 정렬이 필요하면 **Tree-**, 최솟값만 필요하면 **PriorityQueue**, 공유되면 **Concurrent-**.

## 결정 흐름

1. **여러 스레드가 동시에 쓰나?** → 예: `Concurrent*` / `BlockingQueue` (8편)
2. **키 → 값 조회인가?**
   - 기본 → `HashMap` (3편)
   - 넣은 순서/LRU → `LinkedHashMap` (4편)
   - 정렬·범위·가장 가까운 키 → `TreeMap` (5편)
   - 키가 enum → `EnumMap`
3. **중복 없는 집합인가?** → `HashSet` / `LinkedHashSet` / `TreeSet` / `EnumSet` (6편)
4. **매번 최소·최대 하나만 꺼내나?** → `PriorityQueue` (7편)
5. **양 끝에서만 넣고 빼나 (스택/큐)?** → `ArrayDeque` (2편)
6. **그 외 순서 있는 목록** → `ArrayList` (1편)

## 시간 복잡도 표

| 구조 | 조회 | 추가 | 삭제 | 포함 여부 | 순서 |
|------|------|------|------|-----------|------|
| `ArrayList` | O(1) 인덱스 | O(1)* 끝 | O(n) | O(n) | 삽입 순 |
| `ArrayDeque` | 양 끝 O(1) | O(1)* 양 끝 | O(1) 양 끝 | O(n) | 삽입 순 |
| `LinkedList` | O(n) | O(1) 양 끝 | O(1) 양 끝 | O(n) | 삽입 순 |
| `HashMap/Set` | O(1) 평균 | O(1) 평균 | O(1) 평균 | O(1) 평균 | 없음 |
| `LinkedHashMap/Set` | O(1) | O(1) | O(1) | O(1) | 삽입/접근 순 |
| `TreeMap/Set` | O(log n) | O(log n) | O(log n) | O(log n) | 정렬 순 |
| `PriorityQueue` | 최솟값 O(1) | O(log n) | 최솟값 O(log n) | O(n) | 힙 (정렬 아님) |

\* 분할 상환(amortized)

## 자주 하는 실수 Top 5

1. **`LinkedList`를 "삽입이 빠르니까" 고르기** — 실제로는 ArrayList/ArrayDeque가 대부분 빠르다.
2. **`HashMap` 순회 순서에 의존** — 순서가 필요하면 LinkedHashMap.
3. **가변 객체를 키로 쓰고 수정** — 다시는 못 찾는다. 키는 불변(`record` 추천).
4. **`PriorityQueue`를 그대로 출력하고 정렬됐다고 믿기** — `poll()`로 꺼내야 정렬 순.
5. **`ConcurrentHashMap`에서 `containsKey` 후 `put`** — `computeIfAbsent`/`putIfAbsent`로.

## 덤: 불변 컬렉션

```java
List<String> roles = List.of("ADMIN", "USER");   // 수정 시 UnsupportedOperationException
Map<String, Integer> limits = Map.of("free", 10, "pro", 100);
List<Order> snapshot = List.copyOf(orders);      // 방어적 복사
```

- 공개 API의 반환값, 상수, 설정값은 **불변 컬렉션**이 기본.
- `List.of`, `Map.of`는 **null을 허용하지 않는다.**

## 마무리

자료구조 선택은 결국 **"어떤 연산을 가장 많이 하나?"** 라는 질문 하나로 수렴한다.
조회? 정렬? 양 끝? 최솟값? 동시성? — 그 답이 곧 자료구조다.
