> **30초 요약** — 공유 Map은 **ConcurrentHashMap**, 읽기가 압도적인 리스트는 **CopyOnWriteArrayList**,
> 스레드 간 작업 전달은 **BlockingQueue**. `Collections.synchronizedXxx`는 거의 쓸 일이 없다.

## ConcurrentHashMap

- **어떻게**: Java 8+는 빈 버킷엔 **CAS**, 차 있는 버킷엔 **그 버킷 헤드만 synchronized**. 맵 전체를 잠그지 않는다.
- **강점**: 읽기는 락 없음, 쓰기도 버킷 단위라 병렬성 높음. `computeIfAbsent`, `merge`가 **원자적**.
- **약점**: **null 키/값 불가**. `size()`는 동시 수정 중엔 근삿값. 여러 연산을 묶은 "확인 후 행동"은 여전히 원자적이지 않다.

```java
ConcurrentMap<String, LongAdder> hits = new ConcurrentHashMap<>();

// ❌ 경쟁 조건: get과 put 사이에 다른 스레드가 끼어든다
// if (!map.containsKey(k)) map.put(k, v);

// ✅ 원자적
hits.computeIfAbsent(path, k -> new LongAdder()).increment();
```

## CopyOnWriteArrayList

- **어떻게**: 쓰기 때마다 **배열 전체를 복사**해 새 배열로 교체. 읽기는 락 없이 스냅샷을 본다.
- **강점**: 순회 중 다른 스레드가 수정해도 `ConcurrentModificationException`이 없다.
- **약점**: 쓰기가 O(n) + 메모리 복사. **쓰기가 잦으면 재앙.**
- **용례**: 이벤트 리스너 목록, 거의 안 바뀌는 설정/라우팅 테이블.

## BlockingQueue

- **어떻게**: 비면 `take()`가 기다리고, 꽉 차면 `put()`이 기다린다.
- **구현체**: `ArrayBlockingQueue`(고정 크기, 배압 걸기 좋음), `LinkedBlockingQueue`(용량 지정 권장), `PriorityBlockingQueue`, `DelayQueue`.
- **용례**: 생산자-소비자, 스레드 풀 작업 큐(`ThreadPoolExecutor` 내부가 이것).

```java
BlockingQueue<Job> jobs = new ArrayBlockingQueue<>(1_000);

// 생산자
jobs.put(job);           // 꽉 차면 대기 → 자연스러운 배압

// 소비자
Job next = jobs.take();  // 비면 대기
```

## 한눈에

| 필요 | 선택 |
|------|------|
| 공유 해시 맵 | `ConcurrentHashMap` |
| 공유 정렬 맵/셋 | `ConcurrentSkipListMap` / `ConcurrentSkipListSet` |
| 읽기 99% 리스트 | `CopyOnWriteArrayList` |
| 스레드 간 작업 전달 | `ArrayBlockingQueue` / `LinkedBlockingQueue` |
| 논블로킹 큐 | `ConcurrentLinkedQueue` |

## 기억할 것

- "스레드 안전한 컬렉션"이어도 **연산 여러 개를 묶으면 안전하지 않다** → `compute*`, `merge`, `putIfAbsent`
- 카운터는 `AtomicLong`보다 경쟁이 심할 때 `LongAdder`가 유리
- `LinkedBlockingQueue`를 용량 없이 만들면 사실상 무한 → 메모리 폭주 주의
